# Vibecoding Core

Host-owned native agent sessions for Remote Vibecoding.

The sibling telegram-vibecoding repository owns the Telegram interface. Common
Compose/workspace operations live under deployment/workspace and are linked
from the independently tracked workspace root. Its AGENTS.md and README are
owned by RoTorEx/remote-vibecoding, not generated by Core. See BUSINESS.md, docs/architecture.md and TASK.md.

Python 3.13+ and uv are required for development. Run make install and make check.

Each component has independent semantic versions, changelog and annotated Git
tags. The canonical version is its own src package __init__.py; Hatch derives
package metadata from it. uv.lock locks dependencies and records the root
package as dynamic; the installed metadata and wheel carry the concrete version.
Run make release interactively and enter MAJOR.MINOR.PATCH at the prompt; this
checks, updates metadata/changelog and creates a local release commit/tag.
Then make release-push atomically pushes only this repository's main and release
tag and verifies the remote references. Neither command deploys or releases the
sibling. Common deployment continues to select each image revision separately.

Both projects use Vibecoding Kernel 1.3.5. Run make vibe-pull to refresh the local
committed rules; make vibe-kernel-set configures the machine-local kernel path.

### Local speech model

Run `python3 scripts/install_speech_model.py` on the execution host before enabling
voice input. The private default is `~/.cache/remote-vibecoding/whisper-base`;
`speech_model_dir` can override it in Core configuration. No ffmpeg host package
or third container is required. The runtime uses bundled PyAV decoding and never
downloads models. Accept one voice recording up to five minutes / 20 MB. Text and
images continue to work while another session is recognizing speech.

## Continuous integration

This repository stays public. GitHub-hosted Ubuntu runs `make check` and builds a wheel on pushes, pull requests and manual dispatch. Test fixtures use disposable local state and fake native agents; no production SSH keys, native account credentials, live sessions or speech model download are provided. CI does not deploy or start the production service.

## Runtime image dependencies

The container uses Python 3.13 on Debian Bookworm. Patched uv 0.13.4 is
mounted only in the dependency build stage; the final image copies the locked
virtual environment and runs its installed CLI directly. Global pip, uv and
uvx are absent at runtime. Rebuild with a fresh base image for Debian security
updates; preserve the existing user, home and deployment mounts.
