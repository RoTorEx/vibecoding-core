# Local voice acceptance — 24 October 2026

Deployed independent releases: Core 0.1.4 (`9517f7b`) and Telegram Vibecoding
0.1.6 (`01598cb`). Both repositories remain public. Exactly two Compose
containers are healthy; no speech service or paid speech API was added.

## Verified path

A synthetic 2.87-second English Ogg/Opus recording was uploaded through the
actual @GardenSandbox_bot API to its configured owner, downloaded with the
production voice downloader and submitted to the existing QA session. The
transcript was exactly "For this voice test, reply only with OK." Native Codex
returned "OK". The conversation API and frontend renderer placed the transcript
under You. Temporary outgoing test messages were deleted. No incoming updates
were fabricated, no Telegram offsets were advanced manually and the owner's
selected view was preserved. The existing QA session was closed again.

A PNG fixture was uploaded as a Telegram photo, downloaded as Telegram's JPEG,
passed to the same native session and correctly identified as orange. Text,
images and voice use the same durable message contract. Video is unsupported.

## VPS measurements

Host: two vCPUs, 3826 MiB RAM. Model: pinned multilingual faster-whisper base,
CPU INT8, one inference thread, one worker at a time. Each measurement includes
worker imports, model loading, decoding and recognition. Samples are synthetic
speech, not an accuracy benchmark or a latency guarantee.

| Recording | Audio duration | Recognition elapsed | CPU seconds | Worker peak RSS |
| --- | ---: | ---: | ---: | ---: |
| Russian, Milena TTS | 8.44 s | 12.54 s | 8.99 s | 424.73 MiB |
| English, Telegram-to-native test | 2.87 s | 8.91 s | 7.79 s | 402.76 MiB |

The Russian sample used the owner's supplied sentence as source material.
Recognition retained its main request and the words for text, pictures and
voice, but misrecognized the first colloquial word and dropped a conjunction.
The transcript is shown verbatim; no model rewrites or corrects it. A first
standalone English run during deployment took 15.91 s, so cold host contention
can materially increase latency.

A Docker sample during Russian recognition reported 72.87% of one CPU and
357.8 MiB container memory. Process peak RSS and Docker memory accounting differ;
these values are not interchangeable. After recognition and the native voice
reply, Core returned to 65.49 MiB and 0.22% CPU; the worker had exited. The
voice request reached its final native answer in about 15.8 s, including ASR.
Existing host swap use predates this feature; these samples do not establish
whole-host peak usage under multiple concurrent agent workloads.

## Checks and limits

Mac and VPS `make check` passed: 34 Core and 42 frontend tests, Ruff, formatting,
types and CLI smoke checks. Voice tests cover captured target, stable download,
permissions, exact native text, durable transcript reuse, failure without native
execution, concurrent text work, cancellation/reaping, restart and the visible
Stop action while transcribing. Existing image checks pass.

The bound is one voice recording per message, five minutes and 20 MB. Core also
bounds decoded duration and gives its disposable worker a ten-minute timeout.
Actual phone-recorded speech, background noise, weak connectivity and many
simultaneous long voice recordings still need owner-side use. Transcripts go to
the native agent provider as ordinary user text; original recordings are
processed locally and retained in private state.

The model cache is an installed runtime asset at
`~/.cache/remote-vibecoding/whisper-base`, reproducible with
`scripts/install_speech_model.py`. Original QA media and transcript metrics stay
with the QA history; temporary helper scripts and TTS construction files are
removed after acceptance. Model weights are excluded from snapshots; raw voice
uploads remain included by the existing snapshot workflow.
